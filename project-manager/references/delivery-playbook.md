# Delivery playbook

## Estimate and schedule

1. Start with the smallest accepted deliverable and work backward through prerequisites.
2. Estimate active effort for leaf tasks. Leave containers without effort to avoid double counting. Use zero effort for milestone events. State estimate confidence and the source: analogous work, supplied actuals, specialist judgment, or an unvalidated estimate.
3. Obtain each owner's available hours and working calendar. Spread effort across that actual capacity; elapsed duration includes nonworking time and explicit external waits.
4. Check predecessor finish dates, resource conflicts, review and revision windows, access readiness, and approval turnaround.
5. Identify schedule-driving paths and uncertainty. An independent task is parallelizable only when people and tools can actually support it.
6. Keep known work and contingency visible. If a deadline fails, recommend reduced scope or added capacity before pretending it fits. Retain essential QA.

Use a milestone-sized planning horizon or a one-to-two-week detailed window. Expand the next window as inputs become reliable. For a short project, detail the whole project. For a longer project, retain later phase exit criteria and estimated ranges rather than manufacturing precise daily tasks.

## Prioritize and focus

Use this order as a judgment aid, not a mechanical scoring formula:

1. Address imminent blockers or decisions that threaten a committed deliverable.
2. Resolve uncertain prerequisites that could invalidate substantial downstream work.
3. Execute ready work on schedule-driving paths.
4. Deliver high-value outputs and complete nearly finished work.
5. Defer polish and optional improvements with low delivery impact.

Recommend a small active queue. For a solo owner, start with one main task and, when helpful, an alternative that can proceed during a genuine external wait. Do not label everything urgent. Urgent means immediate time-critical consequences; High means milestone-sensitive or substantially enabling; Normal is ordinary committed work; Low is deferrable work.

## Review and recover

Read the latest plan and actual updates. Capture evidence, remaining effort, blocked-since dates, and owner availability. Ask for missing updates only where they change decisions.

Explain delivery confidence in plain terms:

- On track: remaining work fits available capacity and current dependencies, supported by evidence.
- At risk: a material uncertainty or unresolved blocker threatens the forecast, but recovery remains plausible.
- Off track: current scope and capacity forecast a missed commitment.
- Unknown: evidence is insufficient to assess delivery responsibly.

For each blocker, state the missing input, owner to resolve it, downstream impact, recommended next move, and latest useful decision point. Prepare a follow-up draft when useful; do not send it.

Recovery options include splitting delivery, removing optional scope, sequencing differently, getting access sooner, adding qualified capacity, or proposing a changed commitment. Explain trade-offs and recommend one. Mark changes to agreed scope, budget, acceptance, or external dates as proposals until approved.

Measure accepted deliverables and milestone variance. If reporting completion percentages, identify the denominator and method; use weighted leaf-task effort only when defensible. Never count parent effort and child effort together or present a guessed percent as fact.

## Control changes

Use a brief change record:

| Field | Required content |
|---|---|
| Request | What would change and why |
| Baseline | Current accepted deliverable, budget, and date |
| Impact | Added/removed work, resource needs, cost, risks, and forecast |
| Options | Keep baseline, trade scope, add capacity, or revise commitment |
| Recommendation | Preferred option and rationale |
| Decision | Decision owner, needed-by date, approved/rejected/pending |

Replan routine details within the baseline independently. Record material changes only after authorization. Preserve task IDs and actual completion dates. Mark removed work Cancelled rather than deleting delivery history.

## Close and learn

Check accepted outputs, defect disposition, handover files, operating instructions, ownership transfer, and any agreed support or follow-up measurement. Record who accepted what and when. If approval is pending, say delivery is awaiting acceptance.

Capture: what worked, what caused delay or rework, estimate versus actual effort if known, and one to three specific improvements for the next project. Turn lessons into adjusted estimates, earlier checks, clearer briefs, or better templates.
