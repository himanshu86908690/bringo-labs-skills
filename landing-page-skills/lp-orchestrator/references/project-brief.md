# Shared project brief

Keep a single current record in the project's existing workspace. Link artifacts and evidence where practical.

- Project, scope, owner, target environment, launch date if known.
- Audience, buying situation, traffic source and exact message where available.
- Offer and terms, primary action, expected post-action experience.
- Claims with evidence, permission, and status. Mark unverified material separately.
- Success metric, page event, downstream outcomes, and qualification criteria where relevant.
- Receiving system, record owner, required fields, attribution, and test destination.
- Selected stack, approved brand assets, design constraints, and access gaps.
- Current phase, artifacts, evidence, unresolved decisions, approvals, next owner.
- Release URL, rollback location, smoke-test outcome, first review date.

## Education enquiry example

Use a Data Analytics course as a reusable dry-run case. Confirm only that the page gathers enquiries and the sales team handles follow-up. For a simulation, label a Google Search visitor and “Request Course Details” as assumptions. Show the next step without promising an unconfirmed response time. Test one tagged submission through a designated receiver, then test rejected requests and retries. Qualification belongs to sales. Enrollment is optional downstream evidence when the client can share it. Keep fees, placement claims, named tools, curriculum, and course dates out of publishable copy until supported.
